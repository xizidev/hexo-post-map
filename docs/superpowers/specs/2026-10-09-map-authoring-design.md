# 地图选点助手设计

日期：2026-10-09

状态：用户于 2026-10-10 确认设计与实施计划，开始实现；本地体验并明确验收后才进入发版流程。

基线：`hexo-post-map` v0.6.1，提交 `445c7c9339fbf84a43da86ea6b7d75039bc41b96`。

## 1 目标与范围

为 Hexo 作者提供本地可视化工具，完成地图选点、地点编辑、代表位置选择和行程示意线编排，并生成可以直接放进文章 Front Matter 的 `map:` YAML。成功标准是减少手写经纬度和引用关系的错误，不增加读者端地图的复杂度，也不改变本地生成静态文件后上传 Bucket 的发布流程。

沿用现有严格 schema，不增加跨文章的 `place_id`。地点使用 GCJ-02，行程线是连接地点的直线示意，不是导航道路。原有文章、全国地图聚合、轨迹处理和公开生命周期 API 保持兼容。

首版包含新建和粘贴编辑已有地图配置，不自动读取、保存或覆盖文章。地点搜索作为后续独立的可选增强；旅行专题地图和年度足迹卡片不属于本设计。版本号由后续发布流程确定，本轮不修改 package 版本。

## 2 入口与运行方式

通过 Hexo 原生 Console 扩展注册以下命令，而不是增加独立 CLI：

```sh
npx hexo post-map-editor --port 4001
```

该命令为拟新增功能，在当前 v0.6.1 中不可用。

- 默认端口为 4001，只绑定 `127.0.0.1`，不提供 `--host` 或局域网开放选项。
- `--port` 只接受 1–65535 的整数；无效参数报错。端口被占用时退出并提示另选端口，不停止其他服务、不自动改用另一个端口。
- 成功启动后在终端打印本次会话的本地访问地址和 Ctrl+C 停止说明。首版不自动打开浏览器。
- 命令持续运行到作者主动停止。退出时关闭 HTTP 服务和本次会话，不影响博客的 4000 端口服务。
- 作者命令自身不调用 Hexo 的文章加载、生成、部署或监听构建流程，不写入 `source/`、`public/`、博客配置或数据库。
- 普通 `hexo generate`、`hexo clean` 和 `hexo server` 不启动作者服务。

命令仍经过 Hexo 自身的初始化和退出生命周期。Hexo 初始化可能同步 `package.json` 中的 Hexo 版本，其他已安装插件也可能有自己的初始化副作用；作者工具不接管或抑制这些宿主行为。验收应区分宿主行为与作者命令引入的写入，不承诺整个 Hexo 进程绝对零副作用。

不采用生成公开作者页面的方式，避免把编辑器一起上传到 Bucket；也不采用独立在线工具，避免作者另行部署和重复配置 Key。

## 3 配置与地图加载

复用博客已加载的 `_config.yml` 和现有环境变量优先级，仅提取高德 Key、安全模式、底图样式以及详情默认缩放。绝不把整个 Hexo 配置、环境变量集合、文章列表或本地文件路径发送给浏览器。

`post_map.amap.security.security_js_code` 与 `service_host` 仍然只能选择一种，不增加第二套凭据规则。作者命令的注册独立于发布开关；已安装插件但未配置 `post_map`，或 `post_map.enabled: false` 时，仍能打开手动编辑界面。读取有效地图设置与发布开关分离，但不改变原有构建配置校验和禁用语义。

缺失或不合法的地图配置进入手动模式，只显示经过清理的字段级提示，不向 SDK 传递部分凭据。网络、域名限制或 SDK 初始化失败，也只关闭地图相关操作；地点表单、YAML 导入、校验和导出继续可用。

地图复用现有高德 JS API 2.0 加载器和样式设置。SDK 超时后沿用完整刷新才能重试的边界。初始空地图使用固定中心 `[104, 35]` 和缩放 4，不自动获取当前位置，也不依赖 IP 城市定位；导入地图后适配有效地点范围。预览视野变化不自动改写文章的 `map.zoom`。

## 4 页面与写作流程

桌面左侧为主要地图，右侧为有界编辑面板，面板内有“地点”“线路”“导出”三个区域。地点和线路列表在各自容器中滚动，YAML 预览位于导出区域，可折叠。手机改为地图在上、编辑区在下，不用浮层覆盖地图或地图署名。

作者可以从空白地图开始，也可以打开导入框，粘贴已有 `map:` 配置。典型新建流程是点击地图取得候选坐标、填写地点名、确认添加，再按需要设置代表点和线路，最后复制或下载 YAML。点击地图本身不直接增加地点，避免平移、双击缩放或误点产生多余地点。

地图使用与读者端一致的定位图钉和强调色，但采用独立作者样式，不依赖博客主题。地图与列表的选中状态双向同步。点击已有图钉只选中该地点，不创建新候选点，也不打开服务商信息窗或外部地图链接。

首版仅在当前页面内存中保留草稿，不使用 localStorage、sessionStorage、云端保存或后台自动保存。界面常驻说明“刷新或关闭页面会清空草稿，请导出后保存”。不安装阻塞离开的全局 `beforeunload` 监听器。

## 5 地点与代表位置

新增地点自动获得符合现有 ID 规则的 `point-1`、`point-2` 等标识。生成器避开导入 ID 和当前草稿已经使用过的 ID；删除后不在同一草稿中复用。编辑名称、改变坐标或重新排序不会改变 ID。导入 ID 保持原值，首版不提供手动改 ID 的功能。

名称是必填文本，坐标必须是有限数值，并通过现有经纬度范围校验。允许手动输入 GCJ-02 坐标，也允许在地图上微调选中地点；无效输入不能成为新的已提交坐标。地图微调在拖动结束时提交，不在每个拖动事件中重新解析 YAML 或重建页面。

地点数据保留输入数值精度，不为美观随机偏移，不把原坐标统一四舍五入为六位小数。视图可以使用格式化的摘要，但坐标编辑和导出使用真实数值。地图提供商无法预览的合法边界坐标给予明确提示，保留手动编辑和导出能力，不借机收紧原有 schema。

第一个新增地点默认成为代表位置，并在界面中明确标记。作者可以选择其他地点作为全国文章地图的代表位置。多点配置必须具有有效代表点；没有代表点时禁止导出。

删除地点前列出它是否为代表点、是否被线路引用及引用次数。确认删除后清理该点的线路引用；如果删除了代表点，要求作者明确选择新的代表点，不自动换成另一地点。此时即使只剩一个地点，也应完成这次明确选择后再导出。删除唯一地点可以留下空草稿，但空草稿不能导出。

地点列表排序只改变 `points` 的顺序，不改变代表点或已有线路顺序。每行保留名称、坐标摘要、代表点标记及编辑入口，排序同时提供上移和下移按钮，不以拖拽作为唯一操作方式。

## 6 行程示意线

线路区域维护独立、有序的地点 ID 引用序列。作者通过已有地点选择器添加途经项，并可上移、下移或移除途经项。允许同一个地点多次出现，例如 `point-1 → point-2 → point-1`；同坐标地点也不自动合并。

没有途经项时不输出 `route`。仅有一个途经项是未完成的线路草稿，界面提示至少需要两项，并禁止导出，不静默删除该项。两个及以上有效引用才可输出线路；重合地点间没有可见线段，但保留全部引用，不合并或丢弃。未加入线路的地点仍保留并显示。

地图按线路顺序绘制直线段；地点图钉仍表示独立地点，途经序号在有序线路列表中展示，避免一个地点重复出现时只显示一个误导性的序号。编辑线路不改变地点 ID、坐标或代表点。

不请求驾车、步行或骑行规划，不生成导航距离、预计时间或真实轨迹。界面明确标记这是“行程示意线”。

## 7 YAML 导入与导出

### 导入

导入仅接受一个 YAML 文档，根对象只能包含 `map` 字段。输入整个文章、其他 Front Matter 字段或多个 YAML 文档时，提示仅粘贴 `map:` 部分，不猜测正文边界、不截取文章内容。

先执行安全 YAML 解析，再通过现有 `postMapSchema` 和归一化逻辑验证所有引用。重复映射键、未知字段、自定义标签、合并键、循环或超过安全展开上限的别名明确拒绝。别名展开上限为 50；不执行 YAML 内容，也不将对象原型字段合并到配置对象。

作者工具输入和输出各限制为 128 KiB UTF-8 数据，地点最多 200 个，线路途经项最多 1000 个。超过限制明确报错，不截断或取前若干项。这些是作者工具的交互边界，不修改既有 Front Matter 或 Hexo 构建的数量限制。

解析和验证成功后才整体替换当前草稿；替换非空草稿前由作者确认。失败时保留当前地点、线路、选中状态和可用导出内容，错误定位到行列或具体字段。

### 导出

导出只生成一个 `map:` 对象，不带 Front Matter 的 `---` 分隔线，不添加标题、正文、图片、Key、安全密钥、代理地址或编辑器内部字段。经纬度保持 YAML 数字类型，中文、冒号、井号、引号和换行由 YAML 序列化器正确处理，不手拼字符串模板。

只输出 schema 已支持的字段。导入后的 ID、坐标、代表点、线路顺序、重复途经项和已有 `zoom` 保持语义不变；不承诺保留原 YAML 注释、空行、锚点、引号风格或字段排版。

新建单点配置可以不写 `representative`；新增第二个地点时输出已选代表点。导入的显式代表点保持显式输出，不能因只剩单点而丢失作者的选择。新建配置默认不写 `zoom`，作者可显式设置 2–20 的详情缩放；导入的其他有限缩放值保留并提示预览限制，不修改现有宽松校验规则。多点地图沿用自动适配地点范围的行为。

在生成文本后重新解析输出，并通过现有 schema 和归一化校验。只有有效、未超限且与当前草稿对应的输出才能复制或下载。无效草稿不得提供一个看似当前的旧 YAML 导出；预览可以保留旧文本，但必须标注已过期并禁用导出按钮。

复制只能由作者点击触发。剪贴板不可用或拒绝时，提供可选中、带标签的只读文本框手动复制；成功提示使用短小、约三秒自动消失的状态文本。下载通过浏览器生成 UTF-8 `post-map.yaml` 文件，不写入博客目录。

### 真实轨迹保留

已有 `map.track` 作为只读结构保留，字段和值不改写，不自动补齐默认值，也不转成归一化后的驼峰字段。界面提示“真实轨迹配置已保留，选点助手仅预览地点和示意线”。

工具只执行轨迹字段的结构校验，不读取源文件、不校验文件是否存在、不执行隐私裁剪、不播放轨迹。轨迹相对路径及文件内容仍在文章的正常 Hexo 构建中验证。导出的相对路径必须用于原文章或作者自行核对后的目标文章，工具不能保证搬到另一篇文章后仍指向同一文件。

## 8 本地服务安全边界

本地服务使用 Node 内置 HTTP 能力，只提供 `/`、`/assets/editor.js`、`/assets/editor.css` 和 `/api/bootstrap`。前三个路径分别映射包内的固定作者 HTML、脚本和样式。资源路由匹配固定白名单，不把请求路径拼接成文件读取目标，不映射工作区、博客源码、`public/` 或轨迹文件。

每次启动生成一个新的 256 位随机会话令牌，访问地址通过 `#session=<token>` 片段携带令牌。客户端在内存中读取它，通过 `X-HPM-Editor-Session` 请求头请求 `/api/bootstrap`。令牌不作为查询参数，不进入导出、应用存储或高德请求；服务重启后旧令牌失效。浏览器自身可能保留带片段的访问历史，因此这不是隐私历史保证。终端显示的令牌是本次本地工具的访问凭证，不是高德密钥。

- 接受的 Host 必须为本次实际端口的 `127.0.0.1:<port>`；缺失、重复或其他 Host 均拒绝，防止任意域名绑定到回环地址后读到配置。
- 请求若携带 Origin，只允许本次工具的精确 origin。bootstrap 同时要求有效会话令牌；不设置允许跨站访问的 CORS 响应头。
- 静态资源仅允许 GET 和 HEAD；bootstrap 仅允许 GET。其他方法返回 405，未知资源返回 404，无效授权返回 403，不反射输入值或完整错误对象。
- bootstrap 仅返回协议版本 `1`、经过解析的最小地图设置，或不含凭据值的手动模式提示。HTML 和静态脚本不内嵌用户 Key。
- 响应设置 `Cache-Control: no-store`、`Referrer-Policy: strict-origin`、`X-Content-Type-Options: nosniff` 和 `X-Frame-Options: DENY`。跨站请求只发送来源 origin，不发送完整工具 URL；保留地图服务进行来源校验所需的 origin。
- 请求日志和错误不记录 bootstrap 响应、会话令牌、高德凭据、完整 YAML 或源文件路径，不提供配置 dump 或通用反向代理接口。

bootstrap 成功载荷为 `{ version: 1, mode: 'map', mapConfig, defaultZoom }`，其中 `mapConfig` 使用现有 `BrowserProviderConfig` 形状；手动模式为 `{ version: 1, mode: 'manual', message }`，没有 `mapConfig` 或任何凭据。客户端对版本、模式和字段做校验，不接受整个站点配置对象作为备用值。

客户端安全密钥仍是发送给浏览器的值，不能视为秘密；代理模式沿用已配置的服务，不创建新代理，也不绕过高德的域名与额度限制。高德 SDK 和地图资源仍需要联网，本地工具不是离线地图或第三方脚本的安全沙箱。

## 9 模块与打包边界

采用独立作者入口，复用已有规则而不把编辑业务混进详情或全国地图 controller。

| 模块                | 责任与依赖                                                             |
| ------------------- | ---------------------------------------------------------------------- |
| Hexo 命令适配       | 注册命令、校验参数、提取最小配置；只在显式执行时加载作者服务           |
| 作者 HTTP 服务      | 回环监听、固定资源路由、会话授权、停止清理；不接触文章和轨迹           |
| 草稿模型            | 地点操作、稳定 ID、代表点与线路引用关系；纯数据逻辑，不依赖 SDK 或 DOM |
| YAML 适配           | 有界安全解析、序列化及现有领域校验；保留只读轨迹原值                   |
| 作者页面 controller | 表单、列表、导入导出、状态反馈和资源清理；消费草稿模型                 |
| 高德作者适配        | 复用 SDK 加载器，管理候选点、选中点和示意线；不承担 YAML 或文件处理    |

作者 Node 入口及页面资源放在独立的 `dist/author/` 包内目录，由 npm 包携带并由作者服务读取。读者端 `dist/assets/` 的资源名称和公开路由保持不变；生成器继续使用显式读者资源白名单，禁止递归发布整个 `dist/`。

`runtime.js`、详情脚本和全国地图脚本不导入作者模型、YAML 解析器、HTTP 服务或作者 UI。运行时维持现有 8192 字节限制；作者资源增加 npm 包体积，但不得增加普通页面网络请求或读者端运行时体积。

普通页面不暴露作者入口、bootstrap 或会话令牌。作者工具不注册 `window.HexoPostMap` 的新公开方法，不请求 `posts.json`、文章正文或轨迹 JSON，也不改变其版本 1 协议。

## 10 状态更新与错误处理

草稿允许暂时未完成的名称、代表点和线路，但有效提交、地图渲染和导出状态分开。字段级错误就近展示，只有合法坐标传给 SDK。名称及错误信息使用文本节点，不把 YAML 或输入字符串作为 HTML 插入。

表单变更合并更新校验与 YAML 预览，不在每次键入、地图平移或滚动中重建全部 DOM、实例化地图或扫描全列表。选中、修改单点时局部更新覆盖物和对应行。固定列表容器不承担全国地图聚合，也不加载文章图片。

controller 销毁时解绑自己的地图和 DOM 事件、取消定时任务、销毁地图并释放下载 URL。迟到的 SDK、剪贴板或初始化回调不得更新已销毁的页面。pagehide 清理地图资源，若页面通过 BFCache 恢复，则从保留的内存草稿重新挂载一次，不重复绑定监听器。

网络或 SDK 错误显示在地图区域；YAML 错误显示在导入区域；复制失败只降级复制方式。任何一种错误不清空有效草稿，也不让作者误以为文章已经保存或发布。

## 11 可访问性与外观

所有表单字段都有可见标签，代表点选择使用明确的单选语义，控制按钮具有可访问名称和可见焦点环。上下移动、代表点选择、导入确认、复制和下载都能通过键盘完成，点击目标至少 44 px。地图选点不是唯一入口，手动坐标输入不依赖地图加载成功。

列表选择与地图选择不会随意抢走正在编辑字段的焦点。导入确认和删除确认关闭后恢复到发起控件或合理的相邻地点；状态文本使用 aria-live，正常地图加载不反复播报。

保留浅色、深色、强制颜色及减少动态效果支持。强调色和定位图钉沿用插件视觉语言，表单面板优先使用稳定的实色或低成本半透明背景，不增加覆盖整个地图的持续毛玻璃滤镜。地图署名保持可见。

## 12 验收与交付要求

### 纯逻辑和文档

覆盖稳定 ID、删除后的引用处理、代表点缺失、单点到多点、重复途经项、同坐标不同地点、未知字段和合法坐标精度保留。YAML 测试覆盖中文、冒号、井号、引号、多行名称、重复键、别名展开、恶意标签及长度和数量边界。

导入导出往返测试必须证明代表点、线路顺序、重复引用、缩放和只读轨迹值保持语义；省略的轨迹默认字段不能被自动补齐。导出的文本再经真正的现有领域校验，不能只断言包含若干字符串。

### 命令和 HTTP
